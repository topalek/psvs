# Сити Телеком Сервис — сайт и CMS

Публичный сайт регионального интернет-провайдера и административная панель на Laravel + Filament.
Проект содержит русскоязычный сайт, полноценную контентную CMS, управление тарифами, акциями,
новостями, документами, справкой, заявками и ролевой доступ.

> **Важно:** контакты, тарифы, покрытие, реквизиты и юридические тексты в наполнении взяты из
> открытых источников и требуют подтверждения владельцем сайта перед публикацией в продакшене.
> Юридические страницы содержат явные пометки «требуется утверждение».

## Возможности

### Публичный сайт

- Главная страница, интернет для дома и бизнеса, о компании.
- Каталог тарифов с фильтрами по типу клиента, технологии и скорости.
- Акции, новости, оперативные объявления (плановые работы, аварии, расширение сети).
- Покрытие, контакты, документы, FAQ и пошаговые инструкции.
- Личный кабинет и оплата: внешние ссылки без интеграции платежей.
- Формы заявок с серверной валидацией, защитой от спама (throttle) и уведомлением менеджера.
- SEO: канонические URL без завершающего слэша, `sitemap.xml`, `robots.txt`, Open Graph.
- Доступность: семантическая разметка, клавиатурная навигация, контрастные состояния.
- Старые URL перенаправляются на новые (301/302) через таблицу редиректов.

### Административная панель

Панель доступна по адресу `/admin`. По умолчанию открывается тёмная тема; в верхней панели
есть переключатель светлой, тёмной и системной темы. Выбор сохраняется в браузере.

Полноценные страницы списка, создания и редактирования (List / Create / Edit):

- Тарифы
- Пользователи
- Новости и оперативные объявления (единый редактор с полем типа публикации)
- Акции
- Слайдеры
- Слайды
- Статические страницы
- Документы
- Вопросы FAQ
- Справочные статьи

Дополнительно:

- Роли и права: фиксированный набор из трёх ролей, матрица разрешений редактируется на странице роли.
- Заявки: входящий список, статусы, ответственный, внутренние заметки, история статусов, экспорт CSV.
- Медиатека: просмотр и удаление файлов.
- Меню, редиректы, контактные каналы, технологии, услуги, зоны покрытия, настройки сайта.
- Журнал действий (activity log) для изменений контента и доступа.

Удаление и смена статусов выполняются через модальные подтверждения. Создание и редактирование
открываются отдельными страницами с хлебными крошками и возвратом к списку после сохранения.

## Роли

| Роль | Назначение | Доступ |
| --- | --- | --- |
| `admin` | Администратор | Полный доступ, включая пользователей, роли, настройки и журнал |
| `manager` | Менеджер | Контент, тарифы, акции, новости, документы, справка, медиа, заявки |
| `engineer` | Инженер | Только рабочее место инженера (`engineer_workspace.access`) |

Набор ролей намеренно фиксирован: создать или удалить роль через панель нельзя. Администратор
может редактировать разрешения ролей `manager` и `engineer`. Роль `admin` защищена от изменения
и удаления, а администратор не может деактивировать или удалить собственную учётную запись.

## Быстрый старт

```bash
composer install
cp .env.example .env
php artisan key:generate

# Укажите параметры БД в .env, затем:
php artisan migrate --seed
php artisan storage:link
npm install
npm run build
```

Запуск встроенного сервера:

```bash
php artisan serve
```

### Локальная среда OSPanel (Windows)

Проект проверялся в OSPanel:

- URL: `http://psvs.local`
- PHP 8.5.4, MariaDB 11.8
- БД: `psvs`, хост `127.0.1.12`, пользователь `root` без пароля (только локально)

Если `php artisan serve` не может открыть сокет в Windows, используйте виртуальный хост OSPanel.
Если `php artisan storage:link` завершается ошибкой доступа к `bootstrap/cache`, создайте junction:

```powershell
cmd /c mklink /J public\storage storage\app\public
```

## Учётные записи для локальной разработки

Демо-пользователи создаются только при `APP_ENV=local` или `testing`. Пароль всех демо-аккаунтов:
`password`.

| Email | Роль |
| --- | --- |
| `admin@psvs.test` | `admin` |
| `manager@psvs.test` | `manager` |
| `engineer@psvs.test` | `engineer` |

Демо-аккаунты прежней ролевой модели (`content@`, `tariff@`, `leads@`, `support@`, `viewer@`)
при повторном запуске сидера переводятся в роль `manager`, чтобы не терять доступ.

Создать или обновить администратора в любом окружении:

```bash
php artisan app:create-admin admin@example.ru --name="Администратор"
```

Команда запросит пароль интерактивно. Не передавайте пароль в командной строке без необходимости.

## Данные и особенности реализации

- Цены хранятся в копейках (`integer`), в формах администратора отображаются в рублях.
- Богатый текст очищается `App\Support\Html` (Symfony HtmlSanitizer) перед сохранением и выводом.
- Загрузки проверяются на сервере: изображения `jpg/jpeg/png/gif/webp` до 10 МБ,
  документы `pdf/doc/xls/xlsx` до 20 МБ.
- Слайды и секции страниц редактируются через `Repeater::relationship()`; схема полей слайда
  вынесена в `SlideResource::slideFields()` и переиспользуется в слайдере.
- Публичные модели используют `slug` как route key; админка строит ссылки через `getRouteKey()`.
- Канонические URL не содержат завершающий слэш; middleware добавляет 301-редирект.
- Легаси-редиректы обрабатываются до нормализации URL.
- `robots.txt` закрывает `/admin` и `/livewire`, sitemap генерируется из опубликованного контента.

## Продакшен-чеклист

1. Установить `APP_ENV=production`, `APP_DEBUG=false`, реальный `APP_URL` и HTTPS.
2. Настроить БД, `SESSION_SECURE_COOKIE=true`, почту и `LEAD_NOTIFICATION_EMAIL`.
3. Выполнить `php artisan migrate --force`, `php artisan storage:link`, `php artisan optimize`.
4. Запустить queue worker, если включены очереди уведомлений.
5. Сменить/удалить демо-пользователей, создать администратора через `app:create-admin`.
6. Подтвердить у владельца тарифы, контакты, покрытие и юридические тексты.
7. Настроить резервное копирование БД и каталога `storage/app/public`.
8. Проверить формы заявок, экспорт CSV и права ролей на реальных учётных записях.

## Известные ограничения

- Юридические страницы и часть контактных данных — шаблоны, требующие утверждения.
- Названия разрешений в матрице ролей выводятся техническими ключами (`tariffs.update` и т. п.).
- Массовая загрузка медиа в браузере требует ручной проверки: FilePond инициализируется только
  при видимой секции формы.
- Интеграции с биллингом, оплатой и картой покрытия отсутствуют намеренно: используются только
  внешние ссылки и данные, подтверждённые владельцем.
